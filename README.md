# 月次売上報告ツール（monthly-report-tool）

営業所ごとに届く売上明細の Excel を読み、得意先の名寄せ・要確認の判定・集計をして、月次売上報告の Excel（6 シート）を作る道具です。
ブラウザの中だけで動くページを [offrel.com/tools/monthly-report](https://offrel.com/tools/monthly-report) に置いています。このリポジトリは、そのページの中身のうち、判定・集計・Excel の読み書きの部分（UI を除く）を公開したものです。

- 動作の保証はしていません。結果はご自身でお確かめください。
- ライセンスは MIT です（`LICENSE`）。

## 何をする道具か

毎月、営業所から届く売上明細の Excel を 1 つにまとめて「月次売上報告」を作る、という経理の作業を道具にしたものです。
営業所ごとに見出しの言葉や列の並びが違っていても、得意先名の書き方（「株式会社」の有無、全角半角、空白）がそろっていなくても、読み込んで名寄せ・集計し、人が確かめるべき行を「要確認」として一覧にします。

出力は Excel 1 ファイルで、次の 6 シートです。

| シート | 内容 |
| --- | --- |
| サマリー | 営業所ごとの行数・集計した行・要確認の行・読み飛ばし・当月金額・前月金額・前月比。要確認の内訳 |
| 得意先別 | 得意先コード・名前・当月金額・前月金額・増減額・前月比（当月の金額の大きい順） |
| 商品分類別 | 商品分類・当月数量・当月金額・前月金額・増減額・前月比 |
| 担当者別 | 営業所・担当者・当月金額・前月金額・増減額・前月比 |
| 要確認 | 人の判断に回した行の全部（理由つき。集計に含めたかどうかも記載） |
| 統合明細 | 集計に入れた行の全部（名寄せ後の得意先・商品分類つき） |

## 判定の決まり

架空の卸売会社の経理担当との聞き取りで決めた方針です。

| 項目 | 決まり |
| --- | --- |
| 得意先の名寄せ | 得意先コードがあればコードでマスタに寄せる。コードが空欄なら、名前を正規化（株式会社・(株)・㈱などの除去、全角半角の統一、空白の除去）してマスタと照合する。寄らなければ要確認・集計に含めない |
| コードと名前の食い違い | コードはあるが、名前（正規化後）がそのコードのマスタ名と違う行は要確認・集計に含めない |
| 商品分類 | 商品コードで商品マスタの分類を引く。マスタに無い商品コードは要確認・集計に含めない |
| 数量×単価≠金額 | 1 円でも違えば要確認・集計に含めない |
| 対象月外の日付 | 要確認・集計に含めない。「9月1日」のように年の無い日付は対象月の年とみなす |
| 合計行・空行・題名行 | 読み飛ばして、件数だけ数える（要確認には出さない） |
| 同じ内容の行 | 要確認に出すが、集計には両方入れる（本当に 2 回売れた可能性があるため） |
| 返品（負の数） | そのまま集計に入れる |
| 前月比 | 前月のファイルも同じ手順で読んで比べる。無ければ空欄 |
| マスタが無いとき | 得意先は正規化した名前で集計し、商品分類は「未分類」 |

読める日付の書き方: Excel の日付型、`2026/9/1`、`2026-09-01`、`2026年9月1日`、`9月1日`・`9/1`（対象月の年とみなす）、`20260901`、Excel のシリアル値。
数量・単価・金額は `12,000` や全角数字、`△500` のような文字でも読みます。

## 使い方

### offrel.com のページで（インストール不要）

[offrel.com/tools/monthly-report](https://offrel.com/tools/monthly-report) を開き、営業所ごとの売上明細（.xlsx）と対象月、あれば得意先マスタ・商品マスタ・前月分のファイルを選びます。
読み込みから Excel の書き出しまで、お使いのパソコンの中だけで行います。ファイルは送信・保存されません。

### ライブラリとして（Node / ブラウザ）

```bash
npm install   # exceljs と vitest が入ります
npm test      # 単体テスト＋同梱サンプルでの通しテスト
```

```ts
import { buildMasters, makeFileSetup, readGrid, runReport, writeReportWorkbook } from "./src/index";

// 1. Excel（ArrayBuffer）を読み、見出し行と列を自動で推定する
const north = makeFileSetup("売上明細_北営業所.xlsx", await readGrid(northBuffer));
// north.headerRow / north.mapping を直せば、見出しの言葉が違うファイルにも合わせられる

// 2. マスタ（A 列: コード, B 列: 名前, 商品は C 列: 分類）。無ければ省略
const masters = buildMasters(await readGrid(customerBuffer), await readGrid(productBuffer));

// 3. 集計（前月のファイルがあれば previous に）
const { report } = runReport({ ym: "2026-09", current: [north], previous: [], masters });
console.log(report.total.amount, report.checks.length);

// 4. 6 シートの xlsx（ArrayBuffer）
const xlsx = await writeReportWorkbook(report);
```

| ファイル | 役割 |
| --- | --- |
| `src/types.ts` | 型の定義 |
| `src/normalize.ts` | 見出し・得意先名の正規化、数値・日付の読み方 |
| `src/columns.ts` | 見出し行の自動検出、列の自動推定（見出しの語の一致。`COLUMN_ALIASES` に言葉を足せます） |
| `src/process.ts` | 判定規則、集計、報告の組み立て |
| `src/workbook.ts` | Excel の読み書き（exceljs） |
| `src/index.ts` | 入口 |

## サンプル（samples/）

架空の卸売会社（営業所 3 つ）の 2 か月分の売上明細とマスタです。**すべて自動生成の架空データ**で、実在の会社・人物・取引とは関係ありません。

| ファイル | 内容 |
| --- | --- |
| `売上明細_北営業所.xlsx` ほか 2 つ | 当月（2026-09）。北は 1 行目に題名、中央は見出しが短く担当者の列が先頭、南は「金額（税抜）」「備考」列と一番下に合計行 |
| `2026-08_売上明細_北営業所.xlsx` ほか 2 つ | 前月（2026-08）。前月比に使う |
| `得意先マスタ.xlsx` / `商品マスタ.xlsx` | 得意先コードと正式名称 / 商品コード・商品名・分類 |

当月は 5,802 行のうち要確認 43 行（同じ内容の行 14、名前が寄らない 9、金額不一致 8、コードがマスタにない 4、食い違い 3、対象月外 3、商品コードがマスタにない 2）が混ぜてあります。
